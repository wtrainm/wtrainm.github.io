一、什么是 SSTI

SSTI（Server-Side Template Injection），服务端模板注入，是模板引擎与注入结合的产物。

1.1 模板引擎

模板引擎是为了使用户界面与业务数据分离而产生的。它可以生成特定格式的文档，利用模板引擎来生成前端的 HTML 代码。通俗点理解就是：拿到数据，塞到模板里，然后让渲染引擎将塞进去的内容生成 HTML 文本返回给浏览器。

常见的模板引擎：

语言 模板引擎
PHP Smarty, Twig, Blade
Java JSP, FreeMarker, Velocity
Python Jinja2, Django, Tornado

1.2 漏洞成因

由于渲染的数据大多数由用户提供，如果后端没有对用户的输入进行检测和判断，就容易产生代码和数据混淆，从而产生注入。

二、SSTI 前置知识 — Python 魔术方法

在利用 SSTI 进行 RCE 之前，需要了解几个关键的 Python 魔术方法。

2.1 __class__

返回对象所属的类。

2.2 __base__

获取类的基类（父类）。

2.3 __mro__

返回方法解析顺序（Method Resolution Order）。

__mro__[1] 或 __mro__[-1] 的作用等同于 __base__。

2.4 __subclasses__()

获取类的所有子类。

2.5 __init__

类的初始化方法，通过它可以访问到实例的属性和全局变量。

2.6 __globals__

以字典形式返回函数/方法所在模块的全局变量，包括函数、类、导入的模块等。

2.7 __getitem__

实现中括号索引操作，可以用来替代 []。

2.8 __builtins__

Python 的内建模块，包含 eval、exec、open 等危险函数，是 SSTI 中实现 RCE 的重要目标。

八、防御措施

  1. 使用 render_template 而非 render_template_string：前者从文件加载模板，用户输入作为参数传入，不会被解析为模板语法
  2. 严格过滤输入：对 {{、{%、_、. 、[]、'、" 等特殊字符进行过滤或转义
  3. 最小化模板变量：不要在模板上下文中暴露危险对象（如 url_for、config、request 等）
  4. 沙箱隔离：使用 Jinja2 的沙箱模式，限制可访问的内置函数和模块
  5. WAF 规则：部署 Web 应用防火墙检测模板注入特征
